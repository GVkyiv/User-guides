# User Guides: Генератор корпоративных инструкций (MVP)

Рабочий проект для создания качественных инструкций в формате DOCX на базе ТЗ, переписок, видео и презентаций.

---

## 1. Как устроен проект

- `examples/` - папка для эталонных примеров инструкций (файлы `.docx`), которые вы использовали на протяжении 10 лет. На их основе формируются стили.
- `templates/` - базовый шаблон `template.docx` (шрифты, отступы, колонтитулы, стили заголовков, таблицы и рамки).
- `guides/` - рабочие каталоги инструкций, сгруппированные по направлениям (продажи, официальные документы и др.).
  - Пример пути: `guides/продажи/онбординг_crm/`
    - `input/` - сюда кладутся исходные файлы (текст ТЗ, видеозаписи, слайды презентаций, письма).
    - `output/` - сюда скрипт сохраняет готовую инструкцию `.docx` и извлеченные скриншоты.
- `scripts/` - вспомогательные Python-скрипты для сборки документов и извлечения скриншотов.

---

## 2. Пошаговый сценарий работы (MVP)

1. **Положить эталонные образцы**:
   - Положите 1-2 примера существующих инструкций в папку `examples/`.
   - Мы снимем с них фирменные стили и создадим `templates/template.docx`.

2. **Запустить создание новой инструкции**:
   - Назовите направление и тему (например, `официальные документы / согласование договора`).
   - Положите в созданную папку `input/` имеющиеся материалы (ТЗ, видео, слайды).

3. **Обработка материалов**:
   - Текст анализируется сразу.
   - Для видео подбирается оптимальный бесплатный способ: скрипт нарезает ключевые кадры по таймкодам, либо используется разбор через веб-версию Gemini Pro.

4. **Генерация DOCX**:
   - Локальный скрипт компилирует текст, форматирует шаги и вставляет скриншоты в соответствии с корпоративным шаблоном.
   - Готовый документ сохраняется в `output/`.

## 3. Развитие в автономную программу (Фаза 2)

Текущий этап (MVP) сфокусирован на ручной отработке процесса вместе с ассистентом в Antigravity.
В дальнейшем, по мере возникновения потребности, проект получит отдельный гриллинг и будет оформлен в виде полностью автономной программы (CLI или веб-интерфейс). Все скрипты текущего MVP закладываются модульно, чтобы стать ядром будущей программы.
